# Functional checklist

Полный набор тестовой документации проекта включал 58 проверок.

Ниже представлена выборка наиболее показательных функциональных проверок web-приложения, API и базы данных.

## Регистрация

| ID | Проверка | Статус | Баг |
|---|---|---|---|
| WEB-01 | Неавторизованный пользователь может открыть форму регистрации по кнопке «Зарегистрироваться» | Passed | — |
| WEB-02 | Форма регистрации содержит необходимые поля в соответствии с требованиями | Failed | БГ-001 |
| WEB-03 | При заполнении обязательных полей валидными данными появляется сообщение об успешной регистрации | Failed | БГ-003 |
| WEB-04 | При пустом поле «Имя» регистрация недоступна и отображается ошибка | Failed | БГ-004 |
| WEB-05 | При пустом поле «Номер телефона» регистрация недоступна и отображается ошибка | Failed | БГ-005 |
| WEB-06 | При пустом поле Email регистрация недоступна и отображается ошибка | Failed | БГ-006 |
| WEB-07 | Регистрация с уже существующим Email приводит к сообщению о существующем пользователе | Passed | — |
| WEB-08 | При пустом поле «Пароль» регистрация недоступна и отображается ошибка | Failed | БГ-007 |
| WEB-09 | При несовпадении паролей отображается сообщение «Пароли не совпадают» | Passed | — |
| WEB-10 | При пустом поле адреса регистрация недоступна и отображается ошибка | Failed | БГ-009 |
| WEB-11 | Пробелы в начале адреса удаляются после потери фокуса | Failed | БГ-010 |
| WEB-12 | Пробелы в конце адреса удаляются после потери фокуса | Failed | БГ-011 |

## Итог

Выборка демонстрирует проверки:

- позитивных и негативных пользовательских сценариев;
- обязательности полей;
- обработки невалидных данных;
- регистрации и авторизации;
- API;
- сохранения данных в PostgreSQL;
- взаимодействия UI, backend и базы данных.
