# API and Database Testing

В рамках проекта проверялась работа REST API регистрации и авторизации, а также корректность сохранения данных в PostgreSQL.

## Инструменты

- Postman
- Chrome DevTools
- PostgreSQL
- DBeaver

## Найденный дефект

Наиболее показательная ошибка была обнаружена при проверке обязательного поля `phone`.

### Шаг 1 — API

На endpoint:

`POST /api/v1/users`

был отправлен запрос с пустым значением `phone`.

Ожидалось:

`400 Bad Request`

Фактически:

`201 Created`

и создание пользователя.

Дефект оформлен как **БГ-018**.

### Шаг 2 — база данных

После ответа API была выполнена проверка созданного пользователя в PostgreSQL.

Ожидалось, что пользователь с пустым обязательным `phone` не будет сохранен.

Фактически запись присутствовала в базе данных с пустым значением `phone`.

Дефект оформлен как **БГ-019**.

## Вывод

Проверка на нескольких уровнях позволила локализовать проблему: backend не валидировал обязательное поле `phone`, после чего некорректные данные сохранялись в базе данных.

Таким образом, дефект затрагивал не только UI, но и серверную бизнес-логику и целостность данных.
