# Тест-дизайн

Для подготовки проверок формы регистрации использовались техники:

- классы эквивалентности
- анализ граничных значений

Ниже приведены примеры тест-дизайна для основных полей формы.

## Поле «Имя»

Требования:

- длина от 2 до 15 символов
- допускаются русские и английские буквы
- допускаются пробел и дефис
- поле обязательное

### Классы эквивалентности

| Класс | Тип | Пример |
|---|---|---|
| Имя длиной 2–15 символов | Валидный | `Иван` |
| Имя короче 2 символов | Невалидный | `А` |
| Имя длиннее 15 символов | Невалидный | строка из 17 букв |
| Только русские буквы | Валидный | `Иван` |
| Только английские буквы | Валидный | `Ivan` |
| Пробел между словами | Валидный | `Анна Мария` |
| Дефис между словами | Валидный | `Анна-Мария` |
| Цифры | Невалидный | `Иван1` |
| Спецсимволы | Невалидный | `Иван@` |
| Пустое значение | Невалидный | пустая строка |

### Граничные значения

Проверяем:

`1, 2, 3, 14, 15, 16` символов.

---

## Поле «Номер телефона»

Требования:

- длина от 10 до 12 символов
- допускаются цифры и знак `+`
- поле обязательное

### Классы эквивалентности

| Класс | Тип | Пример |
|---|---|---|
| Длина 10–12 символов | Валидный | `+7900123456` |
| Менее 10 символов | Невалидный | `12345` |
| Более 12 символов | Невалидный | `+7900123456789` |
| Только цифры | Валидный | `7900123456` |
| Цифры и `+` | Валидный | `+7900123456` |
| Русские буквы | Невалидный | `7900тест56` |
| Английские буквы | Невалидный | `7900abc456` |
| Пробел | Невалидный | `7900 12345` |
| Дефис | Невалидный | `7900-12345` |
| Скобки | Невалидный | `+7(900)12345` |
| Пустое значение | Невалидный | пустая строка |

### Граничные значения

Проверяем длину:

`9, 10, 11, 12, 13` символов.

---

## Поле Email

Требования:

- длина от 5 до 50 символов
- используются английские буквы, цифры и допустимые символы Email
- поле обязательное

### Классы эквивалентности

| Класс | Тип | Пример |
|---|---|---|
| Email длиной 5–50 символов | Валидный | `test@mail.ru` |
| Менее 5 символов | Невалидный | `a@b` |
| Более 50 символов | Невалидный | строка из 52 символов |
| Английские буквы | Валидный | `test@mail.ru` |
| Цифры | Валидный | `test1@mail.ru` |
| Дефис | Валидный | `test-1@mail.ru` |
| Точка | Валидный | `test.name@mail.ru` |
| Русские буквы | Невалидный | `тест@mail.ru` |
| Пробел | Невалидный | `test @mail.ru` |
| Пустое значение | Невалидный | пустая строка |

### Граничные значения

Проверяем длину:

`4, 5, 6, 49, 50, 51` символов.

Проверка уникальности Email была вынесена в функциональное тестирование, так как она относится к бизнес-логике, а не к проверке класса входных данных.

---

## Поле «Пароль»

Требования:

- длина от 8 до 20 символов
- минимум одна английская буква
- минимум одна цифра
- поле обязательное

### Классы эквивалентности

| Класс | Тип | Пример |
|---|---|---|
| Пароль длиной 8–20 символов | Валидный | `Password1` |
| Менее 8 символов | Невалидный | `abc1234` |
| Более 20 символов | Невалидный | строка из 22 символов |
| Английские буквы + цифры | Валидный | `Password1` |
| Буквы, цифры и знак пунктуации | Валидный | `Pass12,.` |
| Буквы, цифры и спецсимвол | Валидный | `Pass12@#` |
| Без английской буквы | Невалидный | `1234567!` |
| Без цифры | Невалидный | `Password!` |
| Русские буквы | Невалидный | `Пароль12` |
| Пробел | Невалидный | `Pass 123` |
| Пустое значение | Невалидный | пустая строка |

### Граничные значения

Проверяем длину:

`7, 8, 9, 19, 20, 21` символ.

---

## Поле адреса доставки

Требования:

- длина от 5 до 50 символов

### Примеры классов эквивалентности

| Класс | Тип | Пример |
|---|---|---|
| Адрес длиной 5–50 символов | Валидный | `Ленина, 10` |
| Менее 5 символов | Невалидный | `Дом` |
| Более 50 символов | Невалидный | строка из 52 символов |
| Русские буквы | Валидный | `Ленина 10` |
| Цифры | Валидный | `Ленина 10` |
| Пробел внутри значения | Валидный | `Ленина 10` |
| Дефис | Валидный | `Ленина, 10-2` |
| Точка | Валидный | `Ленина, д. 10` |
| Запятая | Валидный | `Москва, Ленина 10` |

### Граничные значения

Проверяем длину:

`4, 5, 6, 49, 50, 51` символ.

---

## Результат

Использование классов эквивалентности позволило сократить количество однотипных проверок, сохранив покрытие различных типов входных данных.

Анализ граничных значений использовался для проверки поведения системы непосредственно около минимально и максимально допустимых значений.
