# Bug reports

## БГ-005 — Регистрация доступна при пустом обязательном поле «Номер телефона»

**Предусловия:**  
Пользователь не авторизован. Открыта форма регистрации. Все обязательные поля, кроме «Номер телефона», заполнены валидными данными.

**Шаги воспроизведения:**

1. Оставить поле «Номер телефона» пустым.
2. Заполнить остальные обязательные поля валидными данными.
3. Нажать «Зарегистрироваться».

**Ожидаемый результат:**  
Регистрация недоступна. Поле отмечается ошибкой, отображается сообщение о необходимости заполнить обязательные поля.

**Фактический результат:**  
Регистрация успешно выполняется с пустым номером телефона.

**Тип:** Functional / Validation

**Окружение:**  
Google Chrome, Firefox, web-приложение «Прилавок».

## БГ-012 — Элементы главной страницы перекрывают форму регистрации

**Предусловия:**  
Пользователь не авторизован. Открыта главная страница.

**Шаги воспроизведения:**

1. Открыть главную страницу.
2. Нажать «Зарегистрироваться».
3. Проверить отображение модального окна.

**Ожидаемый результат:**  
Форма регистрации отображается поверх затемненного фона. Элементы главной страницы не перекрывают модальное окно.

**Фактический результат:**  
Заголовки и другие элементы главной страницы отображаются поверх формы регистрации и перекрывают ее.

**Тип:** UI

**Окружение:**  
Google Chrome, Firefox, web-приложение «Прилавок».

## БГ-016 — При неверном пароле отображается некорректное сообщение

**Предусловия:**  
Пользователь зарегистрирован и не авторизован.

**Шаги воспроизведения:**

1. Ввести Email зарегистрированного пользователя.
2. Ввести неверный пароль.
3. Нажать «Войти».

**Ожидаемый результат:**  
Отображается сообщение:

`Неправильные логин и/или пароль`

**Фактический результат:**  
Отображается сообщение:

`Пользователь с такими данными не найден`

**Тип:** Functional / Validation

**Окружение:**  
Google Chrome, Firefox, web-приложение «Прилавок».

## БГ-019 — База данных сохраняет пользователя с пустым phone

**Предусловия:**  
Через API создан пользователь с пустым полем `phone`.

**Шаги воспроизведения:**

1. Открыть DBeaver.
2. Выполнить SELECT-запрос по Email созданного пользователя.
3. Проверить сохраненные данные.

**Ожидаемый результат:**  
Запись пользователя с пустым обязательным `phone` отсутствует в таблице пользователей.

**Фактический результат:**  
В базе данных присутствует созданный пользователь с пустым значением `phone`.

**Тип:** Database / Data validation

**Инструменты:** PostgreSQL, DBeaver

### Локализация дефекта

Связка БГ-018 и БГ-019 показывает, что проблема не ограничивается интерфейсом: backend принимает невалидные данные и сохраняет их в базе данных.

## БГ-020 — В режиме полета не отображается сообщение об отсутствии соединения

**Предусловия:**  
Приложение запущено на Android Emulator. Интернет-соединение активно.

**Шаги воспроизведения:**

1. Открыть приложение.
2. Включить режим полета через панель эмулятора.
3. Вернуться в приложение.
4. Проверить поведение приложения.

**Ожидаемый результат:**  
Приложение продолжает работу и отображает сообщение об отсутствии соединения.

**Фактический результат:**  
Приложение не падает, но сообщение об отсутствии соединения не отображается.

**Тип:** Mobile / Network

## БГ-022 — Приложение падает при возврате из landscape в portrait

**Предусловия:**  
Приложение запущено.

**Шаги воспроизведения:**

1. Повернуть устройство в ландшафтную ориентацию.
2. Повернуть устройство обратно в портретную ориентацию.

**Ожидаемый результат:**  
Приложение продолжает работу, интерфейс корректно адаптируется к ориентации экрана.

**Фактический результат:**  
Приложение аварийно завершается.

**Тип:** Mobile / Crash

**Дополнительные данные:**  
В ходе проверки были получены логи падения приложения.
